# 技术路线与模块状态

SolarMRV 以分布式光伏的真实设备采集为基础，逐步扩展数据身份、完整性验证和 MRV 应用。以下按代码现状与后续建设方向分别说明。

## 已有实现

| 模块 | 现有能力 | 代码位置 |
|---|---|---|
| 设备采集 | RS485 / Modbus 指标读取、模拟数据包 | [`solar_monitor.py`](../solar_monitor.py) |
| 数据签名 | SM2 签名、结构化载荷生成 | [`solar_monitor.py`](../solar_monitor.py) |
| 自动监测 | 定期采样、CSV 保存、图表与通知 | [`auto_monitor.py`](../auto_monitor.py) |
| 链上读写 | JSON-RPC 查询与 HTTP 交易中继 | [`chain_client.py`](../chain_client.py)、[`chain_relay_v2.py`](../chain_relay_v2.py) |
| 数据合约 | 记录写入、历史查询、最新记录、计数 | [`SolarDataStore.sol`](../contracts/SolarDataStore.sol) |
| 看板接口 | 运行指标与链状态查询接口，含演示回退逻辑 | [`api/app.py`](../api/app.py) |

## 数据复核链路

1. 统一采集数据包的字段、单位和序列化方式，明确设备身份、采集时间与数据包版本。
2. 完整保存签名原文、公钥版本和签名，将原始记录与链上记录一一关联。
3. 补齐独立验签、内容改动识别与公钥绑定检查，形成可复现的验证样例。
4. 将设备采集时间和区块写入时间分开保存，为传输延迟和补传分析提供依据。
5. 对重复记录、缺失字段和异常读数设置明确状态。

## 运行状态与证据记录

- 区分实时数据、历史数据、模拟数据与连接失败状态。
- 保留逐笔上链结果及交易回执，与本地记录建立可检查的对应关系。
- 调整联调脚本，使失败步骤反映在最终结果和退出状态中。
- 为签名、数据转换与接口回退建立不依赖硬件的自动化测试，再增加设备和链节点集成验证。

## MRV 应用扩展

减排量核算模块按适用业务场景配置计算规则、排放因子和统计边界，保留参数版本、源数据引用与计算时间。报表拟覆盖 JSON、Excel 和 PDF，使汇总结果能够回溯到原始记录并复算。

第三方核查接口按项目、设备与时间段组织查询，提供原始记录、签名状态、核算明细和汇总结果，结合访问权限与审计日志记录查询行为。核算引擎与专用核查接口尚未实现。

## 工程扩展方向

- 抽象协议适配层，逐步增加多设备接入。
- 在保留实验 CSV 的基础上引入可查询的数据持久化方案。
- 开展多节点联盟链联调，验证不同参与方的数据访问与同步。
- 增加数据来源、签名状态和计算过程展示。
